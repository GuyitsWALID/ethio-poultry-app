# Design

## Delivery sequence
Correct shared readers first; build the shared read model next; then visual workspace, saved reports/schedules and integrated staging release. Unfinished safeguards must not be hidden by a UI rollout.

## Authorization and evidence
Use current farm assignments and effective warehouse access, never branch membership as a warehouse grant. Check expenses as well as stock. Reject contradictory or unavailable targets. Include flocks operating in the selected interval, using verified placement/movement/completion evidence; final sales are not mortality. Missing evidence remains unavailable.

Use inclusive Addis Ababa operating dates with an exclusive next-day timestamp bound. Calculations read complete, stably ordered pages or fail explicitly; do not return partial totals. Preserve authoritative weighted formulas, separate deaths/culls, incompatible units/FCR types, current balances, period-end balances and period movements.

Reporting locations retain original placement plus verified whole-flock movement intervals. Current farm grants authorize only the corresponding historical location periods; a destination grant never exposes the flock's earlier source-farm history. Records with stored house/farm context retain it on movement day. Otherwise an actual event time must disambiguate a movement boundary; locationless boundary-day evidence is unavailable rather than guessed. Unknown archive completion makes coverage unavailable. Final sale clearance is a departure, not deaths or culls.

Legacy monthly financial aggregates contain no frozen warehouse-source manifest. Managers receive authorized period metadata but not unprovable amounts; direct authenticated aggregate reads are denied too. Their rolling source-expense estimates remain scoped. CEOs keep existing financial history. Mixed production or incomplete consumption evidence cannot form a qualified rolling egg-cost basis. Missing sales costs and non-head-count bird sales have unavailable margins, not zero cost. Growth FCR requires complete compatible weight/feed/population evidence; layer and growth ratios are never blended. Current catalogue stock valuation is labelled as an estimate, not historical accounting value.

## Shared read model
`GET /api/reports/performance` returns typed metrics, chart series, units, coverage and explanation codes from a server-only allowlisted module. Authorize before calculations; private/no-store responses and no service-worker/outbox evidence caching. Failures remain distinguishable from missing evidence and empty results.

Source mapping: Daily Records for production/bird-days/deaths/culls, weight records plus breed/week standards for growth, feeding sessions/closed feed days for planned/actual feed, health events and completed vaccination evidence for health, stock ledger/physical counts for inventory, sales records for selected-sale collections/balances and cost entries/locked periods for qualified costs. Supporting events never duplicate official losses or inventory receipts.

## Presentation
One URL `/app/reports`, seven in-page views: Overview, Production, Feeding, Health, Stock, Sales & Costs, Saved reports. Default 30 inclusive operating days; 7/30/90/custom, maximum 366. Shared authorized branch/farm/house/flock/batch filters; stock warehouse selector; no mandatory batch for Feeding or hidden month substitution. URL retains view, filters and exact saved selection. Clear incompatible children.

Production shows output/quality/growth and targets; Feeding shows actual/planned, feed/bird and valid FCR; Health shows deaths/culls/causes/treatments/completed vaccinations; Stock shows opening/end/current balances, receipts/use/low stock/qualified values; Sales & Costs shows revenue, collections against selected sales, outstanding balances and qualified margins. Overview compares key results and coverage against the previous equal-length period.

Every visual states units/scope, supported takeaway, missing evidence/target caveats and relevant checks. No health diagnosis or claim that lower feed is necessarily better. Warehouse balances are explicitly warehouse-level. Figures expand in-page with accessible text/table alternatives and secondary exact History links.

## Shared live read model (Task 2)
`GET /api/reports/performance` returns versioned typed Production, Feeding, Health, Stock and Sales & Costs sections; Overview composes these sections. Each section carries units, coverage, explanation codes, daily series, supporting figures and authorized History links. Source failures remain failed sections, not zero-valued totals; scope/session/conflict failures reject the request. The API uses private/no-store and Cookie variation on success and error, with safe status/latency telemetry and no protected offline caching.

The orchestration calls server services directly. Sales analytics now has one service used by both legacy and unified routes. Scope-wide feeding reads real sessions without requiring a batch or allocating a batch schedule by today's population. Session plans describe only recorded plans; missing plans are unavailable. Closed flock-days and resolved sessions are separate evidence from synchronized Daily Record consumption. Layer/growth FCR remain distinct. Stock uses the existing stock-window calculation, keeping warehouse/item units separate and current-price value estimates explicitly qualified. A stock selector does not silently narrow unrelated production/sales figures. All sections compare equal inclusive operating periods. Supporting record previews are limited to 200 with explicit full row counts/limit metadata and History destinations; totals/series are calculated before this display limit, using complete stable server pagination or explicit failure.

Each Farm performance attempt now creates one server-only `ReportReadSession`. Named, allowlisted sources are read once across topics and current/previous periods, using the existing complete pagination boundary. Domain readers retain their authorization, location filtering, formulas and resource-provenance capture; standalone legacy readers keep their original query path. The session is bound to organization, actor, role, support session, selected scope and the two-period window. Assignment/store authority is refreshed for each new report. No cross-request, browser, service-worker or persistent evidence cache is introduced. Snapshot consistency retries create a fresh session; atomic revision/publication checks are unchanged. This avoids repeating enough database calls to exhaust the deployed Worker budget.

## Saved reports
Extend management-report interfaces with authorized pagination, retry-safe generation and versioned snapshots. Add `GET /api/reports/management/[id]`; retain download routes. Capture a consistent server evidence set with permission provenance, coverage, comparison basis and generation time, not browser values. Finalize snapshot and audit in one transaction. Claim scheduled executions; revalidate creator/recipients, preserve weekly/monthly semantics and explicit periods. Failed forms stay open.

Managers save one assigned farm (auto-selected if unique); CEOs can save wider scopes. Sharing cannot expand permissions. Immutable v1 reports retain version-specific readers; unverifiable legacy cross-store snapshots are CEO-only, including database reads. Frozen previews are clearly distinct from live results. HTML is printable with visual summaries; CSV escapes formulas in user text while retaining numeric values.

The foundation uses an interim `management-report-v1-scoped` version, retaining the v1 production payload with a server-captured `report_resources` manifest. This is not the planned all-topic v2 snapshot. The manifest records the selected authorized farm context and warehouse identities used by the stock-derived figures. Missing warehouse lineage is explicitly incomplete, never reconstructed from current permissions. Publication checks the creator and every recipient, and RLS plus service-only readers recheck current access on each read. Failed scoped attempts contain no snapshot and use a generic persisted failure message; they remain visible to their currently authorized manager without leaking private-store diagnostics. Legacy v1 snapshots stay immutable and CEO-only. Authorized saved listing now uses 50+1 keyset pagination with precise timestamps; exact `saved_report` selection opens a sandboxed frozen preview independently of loaded pages.

## Compatibility and release
Task 4 now publishes `management-report-v2`: full server-generated domain sections, coverage, comparison basis, readable context, resource manifest and evidence revision. Triggers on reporting source/permission/location/metadata tables advance a tenant revision in the source transaction. Capture reads the revision before/after, retries up to three times, and rejects failed source sections. Publication holds/rechecks the same revision inside existing snapshot/audit/receipt finalization, after current creator/recipient authority checks. This detects changes across independently paginated readers without treating browser values as evidence. Changed publication fails without partial report/audit persistence; retry identifiers and worker leases remain authoritative. Old v1/v1-scoped snapshots and their renderers are retained unchanged.

V2 frozen previews and HTML/CSV downloads can translate labels/calendar for the viewer without mutating stored evidence or its hash. Saved controls preserve entered schedule values on failure. Selected stock warehouse is included in generation scope; managers with one assigned farm receive that farm automatically when saving. HTML contains static visual summaries and tables, no executable scripts/external resources; CSV protects user text. Report responses remain private/no-store and outside offline storage.

Today-enabled CEOs/managers get one Farm performance sidebar entry; disabled organizations/Admin remain unchanged. Resolve Analytics/advanced/saved links in-page without interstitials. Preserve exact finding/approval/financial-period/cost-entry targets. Translate labels, controls, explanations and errors EN/AM, use Ethiopian display in Amharic, Gregorian API dates, Addis boundaries, user content untranslated, 48px targets, focus and keyboard access.

Focused regressions during implementation; full suite, TS/lint and production/Cloudflare builds once integrated. Investigate staging Unavailable eggs without fabricated records or weakened assertions. Any new migrations are forward-only, Docker-tested then staging-tested before notmain. Production separately approved.
